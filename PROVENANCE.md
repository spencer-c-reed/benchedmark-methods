# Provenance, exclusions and redactions

The code and four rules files were curated from deployed source revision `65c29005001fe4a21b1f3cbf38a6dd4466a55f6f`, resolved on Nov 2, 2026. The serving inventory identified the four rules paths and the `nfl-proto-4` / `nfl-restart-1` windowed templates in non-void league configurations. Full-game agents use the included v2 block registry. A current snapshot includes historical/ended configurations and does not prove which historical file bytes every call used. This release is a current methods snapshot, not a reconstructed historical freeze.

All 19 deployed `bm/score/*.py` modules and `bm/engine/scoring.py` are included, together with `bm/publish/boards.py` and the transitive Python imports identified by static import analysis. No result was generated from real league data in preparing this package. Importing the modules is not proof that all operational entrypoints are standalone; external data, league inputs and runtime services remain necessary for those entrypoints.

`SOURCE-MANIFEST.json` records source and released SHA-256 values. Rules and both requested windowed prompt modules are byte-for-byte copies. Scorer source retains explanatory text; personal attribution in one scorer comment/docstring is replaced with generic operator wording. Supporting modules lose comments and docstrings (including operational anecdotes and embedded historical counts) and are reformatted by Python's AST unparser. Personal attribution in diagnostic strings is generalized. These transformations do not change scoring formulas. Prompt-bearing modules retain the actual prompt strings. The two requested general template modules contain no held-out scenarios and are unchanged. Held-out house-probe scenario prompts, selection logic and timing in `bm/league/private.py` are redacted: the two generation entrypoints raise `NotImplementedError`, and the probe list is empty. This deliberately prevents reproducing the private challenge pool. Some ancillary module prose refers to internal design sections; those references are not public links or claims that the internal document is released.

The config files are curated: bot cutoff and prompt-variant values are retained without source comments; successions retain scoring-relevant effective fields but omit evidence, changelog quotations and watch entries; entrants retain only id, display name and color; lanes retain only lane and adapter. They are metadata, not live deployment configuration. No provider routing credentials or spend authorizations are included. External data-source rights remain with their owners; Apache-2.0 covers this released code and documentation, not absent sports/market/provider data.

Excluded by construction: private repository history, results, standings, picks, cost/readout outputs, league configurations and logs, decisions, rendered prompts containing league state, notebooks/memos, held-out replay/probe scenarios, sports and market snapshots, credentials, personal information, internal communications and funding material. Only the newly created methods repository's clean release history is published.

Methods prose was newly written from the current `/methodology/` source, public plan, `rules/policies.md`, `plan/REGISTRATION-NOTES.md` and the relevant `plan/DESIGN-V1.md` sections. Those source documents contain internal details and outcomes and are not copied wholesale. The dated changes are a digest, not a claim to publish every operational change. Synthetic arithmetic examples reuse the existing staged demo and contain no experimental observations.
